Attack Type 1 · Indirect Prompt Injection
The hidden instruction the human never saw
Indirect prompt injection is a sophisticated attack where an attacker embeds hidden instructions within seemingly harmless content — in this case, a newsletter email. When the AI agent processed the email, it found instructions it treated as legitimate commands.

The attack bypasses user awareness entirely. The human never opened the email. The AI did — and it couldn't distinguish between the newsletter content it was asked to summarise and the injected instruction it was never supposed to receive.
Why it's dangerous: Traditional security defences scan for malware and suspicious files. A hidden HTML comment in a newsletter triggers nothing. The AI becomes an unwitting accomplice — executing attacker instructions using its own legitimate access.
What happened next: The agent now believes its instructions include accessing the pricing file and sending data externally. It will do this using its own tools — the ones it was given legitimate access to.

Attack Type 2 · Tool Compromise
When the tools you trust work against you
Attackers exploit AI by compromising tools or embedding hidden instructions in tool descriptions. The agent called send_digest() believing it would email the sales team. The tool's description said it would. The tool's actual behaviour was different.

Because AI agents chain tools together automatically, one compromised tool created a cascade: the file reader accessed sensitive data, the email tool silently forwarded it. Neither action looked anomalous individually.
The chain effect: A malicious tool might leak files or send unauthorised emails. Since AI chains tools together, one compromised tool can disrupt entire workflows — and the agent will continue executing, unaware anything is wrong.
What makes this hard to catch: The agent used tools it was legitimately given access to. Every action was permitted. The problem was that the tools themselves were compromised — and the agent had no way to verify that.

Attack Type 3 · Data Exfiltration
The breach that looked like a routine email
AI can be tricked into leaking data through channels that look completely legitimate. In this case, the agent extracted the pricing file and sent it externally — but the email came from an authorised address, passed DLP checks, and triggered no SIEM alerts.

The data exfiltration was undetected because the agent used a legitimate, trusted communication channel. Every defence that looked for suspicious behaviour was satisfied. The attack succeeded precisely because nothing about the outbound email looked wrong.
Why detection is so difficult: Traditional security tools ask "did an unauthorised actor send this?" The answer was no — an authorised AI agent did. The question we need to ask is: "did the agent send something it was instructed to send by an attacker?" That requires a different kind of monitoring entirely.
The complete chain: One injected instruction in one email led to unauthorised file access, a compromised tool silently BCCing an external address, and 2,847 rows of customer data leaving the organisation — all without a single alert.
