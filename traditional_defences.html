⚠ What the check cannot see
→A security check looks for things that look dangerous. A polite, well-written instruction passes every time — even if its real purpose is to steal data.
→Think of it like a bouncer checking IDs. A fake ID that looks real gets through. The bouncer can't read minds — and neither can a security scanner.
What good defence looks like
Security that understands what an instruction will actually do — not just whether it looks safe on the surface.

⚠ What the check cannot see
→The access system asks: "is this agent allowed to do this?" The answer was yes — every time. It never asked why the agent needed calendar, email, customer data, and outbound email all at once.
→It's like giving a contractor a master key because they need access to a few rooms. If something goes wrong, they can go everywhere. One trick was enough to use all of that access at once.
What good defence looks like
Give AI agents access only to what the current task needs — nothing more. Accessing your calendar, email, and customer database in the same session should raise a flag.

What good defence looks like
Treat every document as potentially untrusted, regardless of where it came from — and check content for hidden instructions before the AI reads it.

Four gaps. One pattern.
Existing tools ask "does this look dangerous?" — not "will this cause harm?" That's the gap attackers walk through.
Polite-sounding attacks
A security scan can't tell a friendly-sounding instruction from a malicious one. If it looks normal, it gets through.
Missing the full picture
Security tools check each action in isolation. They don't remember what happened earlier — so earlier manipulation goes unnoticed.
Too much access
AI agents need broad access to do their job. One trick is enough to turn all of that legitimate access into a data breach.
Trusted back channels
Security watches the front door. Attacks arrive in documents, emails, and websites that the system already trusts — through the back window.
The key takeaway for sales conversations
→Existing security tools were not built for AI agents
→Attacks can look completely normal and still cause serious harm
→The more access an AI has, the bigger the risk if it's tricked
→Trusted sources are not the same as safe sources
